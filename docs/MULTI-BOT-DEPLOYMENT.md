# 多主管机器人部署方案

## 最终形态

一个飞书工作群中放入多个独立机器人身份：Kiya总管、考研主管、英语主管、科研主管、技能与作品集主管、新闻研究主管、申请主管。健康主管建议只私聊，不放在普通工作群。

每个可见身份必须对应一个独立的飞书自建应用。一个飞书应用只能呈现一个机器人身份，无法由后台代码生成多个群成员。所有应用共用同一个 Node 服务、同一个数据库和同一个模型 API 账户。

## Token 触发边界

只有以下情况进入模型调用：

1. 主人在群里明确 `@某个主管` 并发送文本任务。
2. 主人私聊某个主管并发送文本任务。

普通群消息、没有提及主管的消息、其他成员消息、机器人消息、图片和系统事件在调用模型前被过滤。定时 AI 任务默认不存在，因此不会自行产生模型费用。健康检查、飞书长连接和多维表格读写本身不消耗模型 Token。

## 飞书端重复步骤

每个主管应用都需要：

1. 开启机器人能力。
2. 选择长连接事件订阅。
3. 添加 `im.message.receive_v1`。
4. 开通“接收群聊中 @ 机器人的消息”和“以应用身份发送消息”。
5. 创建版本并发布到当前组织。
6. 将机器人加入同一个工作群。健康主管建议仅发布后私聊使用。

复制 `config/bots.example.json` 为 `config/bots.local.json`，逐个填写 App ID 和 App Secret。该文件已被 Git 忽略，不提交到仓库。

## 云端部署

长连接要求一个持续运行的进程，不能使用会在请求后立即休眠的普通函数。可选目标包括国内轻量云服务器、持续运行的容器服务或支持常驻进程的 PaaS。

构建并运行 Docker 镜像：

```bash
docker build -t feishu-growth-os .
docker run -d --restart unless-stopped -p 4280:4280 \
  -e FEISHU_BOTS_JSON='机器人配置JSON' \
  -e FEISHU_OWNER_OPEN_ID='主人open_id' \
  -e AI_API_BASE_URL='兼容接口地址' \
  -e AI_API_KEY='模型密钥' \
  -e AI_MODEL='模型名称' \
  feishu-growth-os
```

生产环境应使用云平台 Secret 管理，不把上述密钥写进 Dockerfile、镜像或 GitHub。部署完成后通过 `/api/health` 查看已配置机器人数量和实际模型调用计数。
